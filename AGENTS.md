# Інструкції для AI-асистента

## Загальні правила

- Відповідай українською мовою.
- Пиши код у стилі, який уже використовується в проєкті (чистий JavaScript, Node.js).
- Не змінюй архітектуру без явної потреби.
- Не видаляй існуючий функціонал без пояснення.
- Перед великими змінами коротко пояснюй план.
- При кожному внесенні змін коду інкрементуй patch-версію в `package.json` (або відповідний номер згідно з SemVer: `major.minor.patch`).
- Не перезбирати інсталятор після кожного оновлення чи внесення змін у код додатку. Інсталятор збирається лише за явною командою користувача ("Збери інсталятор", "Збери білд" або `npm run dist`).
- Дотримуйся єдиного візуального стилю для системної інтеграції (іконки трею, системні сповіщення, оформлення вікна).
- Не ігноруй файли в проєкті, позначені в `.gitignore`.

## Специфікація та Архітектура проєкту (Electron app: alert_desktop)

Застосунок `alert_desktop` — це десктопний клієнт для моніторингу повітряних тривог на базі Electron:

1. **Головне вікно (BrowserWindow):**
   - Відображає веб-сторінку `https://alerts.in.ua/`.
   - Завантажує сторінку з надійними параметрами безпеки.
   - Відкриття зовнішніх посилань (сторонніх доменів) перехоплюється та відкривається у системному браузері користувача за замовчуванням (`shell.openExternal`).
   - Перехоплення події `close` на вікні: вікно не знищується, а приховується (`event.preventDefault()`, `win.hide()`).

2. **Системний трей (Tray):**
   - Постійно присутній у системному треї (області сповіщень).
   - Візуально інформує про поточний статус:
     - звичайний стан (немає тривоги / відбій);
     - стан тривоги (активна повітряна тривога);
     - помилка / відсутність зв'язку із сервером.
   - Одинарний/подвійний клік на іконці трею показує або ховає головне вікно.
   - Контекстне меню трею (правий клік): "Показати/Сховати", "Перевірити зараз", "Налаштування", "Вихід".
   - Повне закриття застосунку відбувається виключно через команду "Вихід" у треї або системний пункт `app.quit()`.

3. **Підвантаження даних із сервера (HTTP Polling):**
   - Фонові періодичні запити (HTTP polling через `fetch`/`axios`) до API для отримання актуального стану тривог.
   - Опитування виконується в головному процесі (Main Process) без блокування UI.
   - Порівняння нового стану з попереднім: при появі або відбої тривоги оновлюється іконка трею та викликається нативне системне сповіщення (`Notification`).
   - Обробка помилок мережі: таймаути, перепідключення, індикація офлайн-статусу без аварійного завершення роботи.

4. **Безпека Electron (Обов'язкові вимоги):**
   - `contextIsolation: true` та `nodeIntegration: false` у налаштуваннях `webPreferences`.
   - Віддалений веб-контент не повинен мати доступу до середовища Node.js або системних API.
   - Якщо потрібна взаємодія між віддаленою сторінкою/локальним UI та головним процесом — використовувати строго обмежений `preload.js` через `contextBridge`.
   - Блокування повторного запуску через `app.requestSingleInstanceLock()`. Якщо копія вже запущена — фокусувати існуюче вікно.

## Структура проєкту

Повний актуальний опис структури модулів та файлів ведеться у документі `STRUCTURE.md`.

- Перед роботою з кодом обов'язково звіряйся зі `STRUCTURE.md` для точкового доступу до потрібних файлів.
- При додаванні, перейменуванні чи видаленні файлів/модулів оновлюй `STRUCTURE.md`.
- Орієнтовна модульна організація:
  - `src/main/`:
    - `main.js` (ініціалізація застосунку, життєвий цикл, single instance lock)
    - `window.js` (створення та керування станом BrowserWindow)
    - `tray.js` (керування системним треєм, зміна іконок, контекстне меню)
    - `api.js` (фоновий сервіс HTTP-опитування стану тривог, обробка відповідей)
    - `notifier.js` (вивід нативних системних нотифікацій та звуків)
    - `config.js` (збереження та завантаження налаштувань користувача)
  - `src/preload/`:
    - `preload.js` (безпечний міст contextBridge за потреби)
  - `assets/`:
    - `icons/` (набір іконок для трею: `tray-normal`, `tray-alert`, `tray-offline`, а також іконка програми `app-icon`)
  - `scripts/` (допоміжні скрипти тестування, збірки тощо)

## Стиль коду

- JavaScript: дотримуйся сучасного стандарту ES6+, модульного стилю (CommonJS або ESM відповідно до конфігурації `package.json`).
- Зрозумілі назви змінних та функцій.
- Асинхронний код: використовуй `async/await` з обов'язковою обробкою винятків у блоках `try/catch`.
- Не додавай зайвих залежностей та абстракцій: віддавай перевагу вбудованим API Electron та Node.js.
- Намагайся перевикористовувати та доповнювати наявні модулі.

## Коментарі

- Не пиши очевидних коментарів.

## Тестування та валідація

- Перед здачею коду завжди перевіряй синтаксичну коректність (наприклад, `node --check <шлях_до_файлу>` або лінтером).
- **Smoke-тест запуску:** перевіряй, що застосунок стартує без помилок парсингу, ініціалізує трей та створює вікно.
- Перевіряй стійкість до збоїв:
  - поведінка при відсутності інтернету (offline mode у HTTP-полінгу);
  - коректне згортання в трей при натисканні 'X';
  - вихід із програми без зависання фонових таймерів або процесів.

## Автоматизація рутинних процесів (Швидкі запити)

Для швидких ізольованих запитів користувача дій строго за контекстом запиту:

- **"Запусти застосунок" / "Запусти":**
  - Виконай: `npm start`
  - Не змінюй версії та не проводь зайвих тестів.
- **"Збери білд" / "Збери інсталятор":**
  - Виконай: `npm run dist` (або `npm run build:installer`). Команда запакує Electron через `@electron/packager` та скомпілює інсталятор Inno Setup через `ISCC.exe` у файл `dist/AlertDesktop-Setup-v<версія>.exe`.
- **"Перевір" / "Запусти тести":**
  - Виконай: `npm test` або smoke-тест перевірки синтаксису модулів.
- **"Підніми версію" / "Онови версію":**
  - Інкрементуй patch-версію в `package.json` (`npm version patch --no-git-tag-version`).

## Збірка та Інсталятор (Inno Setup)

- Для створення інсталятора використовується **Inno Setup 6** (файл налаштувань: `installer/setup.iss`).
- Автоматизація збірки виконується через скрипт `scripts/build_installer.js`:
  1. Перевіряє наявність Windows-іконки `assets/icons/app-icon.ico` (генерує через `scripts/generate_ico.js` за потреби).
  2. Автоматично знаходить системний компілятор Inno Setup (`ISCC.exe`).
  3. Пакує додаток у `dist/unpacked/AlertDesktop-win32-x64` за допомогою `@electron/packager` (суворо виключаючи `.env`, `dist`, `.git`).
  4. Запускає компіляцію `ISCC.exe /DAppVersion=<версія> installer/setup.iss`.
  5. Створює готовий автономний файл інсталятора `dist/AlertDesktop-Setup-v<версія>.exe` (підтримує українську та англійську мови, створення ярликів, автозакриття процесів, налаштування автозапуску та чисте видалення).
- **ВАЖЛИВО:** Після кожного звичайного оновлення коду, фіксу багів чи підняття patch-версії інсталятор автоматично **НЕ** перезбирається, щоб не сповільнювати цикл розробки. Збірка інсталятора виконується тільки за явною командою користувача ("Збери інсталятор", "Збери білд" або `npm run dist`).

## Правила роботи з промптами

- Plan mode: / планування: - режим планування без редагування коду.
- Ask mode: / запитання: - режим відповідей на запитання асистентом без редагування коду.
- Якщо користувач просить план:
  - Запропонуй кілька чітких варіантів реалізації.
  - Коротко опиши плюси й мінуси кожного варіанту.
  - Не пиши код, поки користувач не обере варіант.
- Якщо користувач надіслав стек помилки:
  - Проаналізуй стек, не роби припущень без коду.
  - Знайди місце помилки в кодовій базі.
  - Запропонуй точкове виправлення та поясни причину.
- Якщо користувач пише "покращ" без деталей:
  - Запитай уточнення або запропонуй 2-3 конкретні напрямки покращення (продуктивність, читабельність, архітектура).
- Якщо користувач просить додати фічу, яка суперечить архітектурі:
  - Поясни ризики.
  - Запропонуй альтернативний спосіб реалізації, який краще вписується в проєкт.
